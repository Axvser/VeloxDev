# 记忆写作密度

> 适用范围：`memory/` 下 agent 落笔的一切文字。
> 本文是「哪些句子该删」的唯一事实源；目录结构、两份必备与维护时机见 [模块记忆维护](memory-maintenance-specifications.md)。

**总原则：如无必要，宁缺毋滥。** 只写能直接帮下一个 agent 理解项目的句子；复述、铺垫、过渡、同义反复一律删。目的是减少上下文干扰、加快访问，不是把记忆写全。

**判据**：删掉这句，读者会不会更容易做错或走错路？不会，就删。

## 一、赘叙类型

| 类型 | 长什么样 | 改法 |
|---|---|---|
| 因果解释型（含避坑向） | 「因为…所以…」「否则会…」「别把它当缺陷去修」 | 留结论、后果、锚点；推导归提交信息，坑归 `pitfalls.md` 或该平台的坑节 |
| 历史叙述型 | 「已删除」「以前」「不再」「2026-xx 起」 | 只写当下状态；不存在的成员直接删 |
| 副本型 | 类型/成员/文件清单、文件大小排序、csproj 属性、版本号字面量、基准报告的表格结构 | 只留代码/IDE 看不出来的不变量与后果；数字与版本以 csproj / 现跑结果为准 |
| 同义反复型 | 前后分句说同一件事 | 留一句 |
| 说教/铺垫型 | 「改的人得自己守」「别顺手做」「本文只写…」「本文不抄」「见…不冲突」 | 删；规则写进规范，指针只留路径，不留旁白 |
| 修辞强化型 | 「唯一」「真正」「值得单独记住」「这一节是全文最重要的」「…不是抄来的」 | 换成事实；没有事实就删 |
| 计数播报型 | 测试条数、通过/跳过/失败数、耗时、构建结果、文件/类型/接口计数、复现计数的命令、测试过程/覆盖清单、发布 run 号/TRX 路径 | 全删；要数字现跑 `dotnet test` / `ls`。测试名可留作锚点，测试机制叙述不留 |
| 跨文件重复型 | 同一事实在 `architecture.md`、`extension.md`、`pitfalls.md`、另一模块或另一平台的记忆各写一遍；逐家点名只为证明「别家能照抄什么」的横向清点 | 留一处，其余改指针；横向清点只留分歧双方 + 指路 |
| 过期断言型 | 与代码不符的旧结论、「全模块唯一 / 从未 / 都不存在」这类无法核验、新增成员即过期的断言、「推断未实测」 | 核到不符就改/删；核不到就标条件或删；不要拿行号或 commit 当依据 |
| 未来推测型 | 「将来版本可能补上…」「下次大概会…」 | 只写当下 |
| 维护建议型 | 「要保持一致就改成…」「优化时先看这里」「做 X 时别忘了同步 Y」 | 只允许在 `extension.md`（官方做法 / 捷径 / 联动清单）；architecture 与 pitfalls 里删 |

**过期断言型不是赘叙，是会误导读者**：它和其余类型一样要清，但删之前先回代码核实，改成当下事实或直接删。

**计数播报型的边界**：单次实测的**行为依据**（某平台在某条件下的 px、帧数、阈值、耗时）不是计数播报 —— 它回答「这条结论还成不成立」，必须保留并写明测量条件。被删的是与代码逻辑无关、每次增删都会过期的清点与流水账。

## 二、两条红线

1. **不删事实**：当下状态、`文件:符号` 锚点、带条件的行为数字必须保留；删的只是包裹它们的措辞。
2. **不改规范**：`memory/specifications/` 由用户口述；本文件也是用户口述后 agent 落笔，agent 不自行改正文。

## 三、自查

- 每句都回答「它帮读者理解了什么」；答不出就删。
- 同一事实只出现一次：`architecture.md`、`extension.md`、`pitfalls.md` 不互抄。
- 没有计数播报、历史叙述、副本清单、过期断言。
- 改到的旧记忆是**改**那一句，不是下面追加一段。
- 标题/条目编号唯一，交叉引用指向存在的节（不写悬空的「§八·4」，不出现两个 P8）。
