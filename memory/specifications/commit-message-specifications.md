# 提交信息规范

> 用户口述、agent 落笔。约束**提交信息怎么写**。
> 触发：**每次 `git commit` 之前**。
> 本文是这一主题的唯一事实源。相关的另一面在 [code-comment-specifications.md](code-comment-specifications.md) §三：「推导过程、失败过的方案、量到的数字」放这里，不放代码注释。

---

## 一、格式

```
[类型][模块] English subject line

[what] 这一笔改了什么
[why] 为什么必须改 —— 不改会出什么问题
[how] 关键手法，以及依据落在哪
```

### 首行

- `[类型][模块] ` 之后接**英文**标题：一句话说清做了什么，**结尾不加句号**。
- 两个方括号**紧挨着**，括号内**前后不留空格**。写 `[bugfix][WorkflowSystem]`，不写 `[ bugfix ] [ WorkflowSystem ]` —— 历史里两种都出现过，以后只认前者。
- 一行只放**一组**标签。历史里有把两笔改动塞进一行的（`[ file ] … [ optimize ] …`），那要拆成两笔。

### body

- 空一行后开始，三段各以 `[what]` / `[why]` / `[how]` 起行，正文用**中文**。
- `[what]` 必写。`[why]` 与 `[how]` **有实质内容才写**；没有就整段不写，不要写「无」「同上」凑格式。
- `[why]` 写**因果** —— 不这么改会出什么问题。不是把 `[what]` 换个说法再说一遍。
- `[how]` 写**关键手法与依据**。引到具体位置时写 `文件:行`，**不要用「见上一笔提交」代替**：读者手里只有工作区。
- 长文推导就该待在这里，一段不够就多写几段 —— 这是它唯一该待的地方。

## 二、类型词表（闭集，8 个）

| 类型 | 用于 | 历史里出现过的变体 |
|---|---|---|
| `config` | 构建、包引用、CI、仓库配置、版本号 | `[ file ]` 里属配置的那部分 |
| `feature` | 新增能力 | `[ feature ]` `[Feature ]` |
| `bugfix` | 修缺陷 | `[ fix ]` `[ bug fix ]` `[ BugFix ]` |
| `refactor` | 不改行为的结构调整 | `[ 重构 ]` |
| `perf` | 性能 / 内存改善（仍不改行为） | 历史里主流就是 `perf(...)`（10 笔）；方括号形式的 `[ optimize ]` `[ Optimization ]` 2 笔也归这一格 |
| `doc` | 文档，含 `skills/` 与 `memory/` | `[ doc ]` |
| `test` | 只动测试 | — |
| `chore` | 以上都不是的杂务 | `[ Demo ]` 等 |

**这是闭集。** 要用第 9 个，先改本文件再加进提交；不要在提交里现造一个。

**统计词表时要把两套写法都数进去。** 方括号式的历史只有 48 笔，其余绝大多数走的是 `type(scope):` —— 只看方括号形式会得出偏的结论。例：性能类在 `type(scope):` 形式里有 10 笔（`perf(transition)` 等），而 `[ optimize ]` / `[ Optimization ]` 只有 2 笔；本表因此以 `perf` 为准，而不是以笔数少的 `optimize` 为准。

## 三、模块标签

- 取 `Src/` 下的**模块名**，与 [`memory/modules/`](../modules/) 的目录名对齐：`Core`、`TransitionSystem`、`WorkflowSystem`、`Compiler`。这样 `git log --grep` 与记忆目录能直接对上。
- 平台面用它自己的名字（`WPF`、`Avalonia`、`WinUI`、`MAUI`、`WinForms`、`Razor`、`Jalium`），或「模块名 + 平台名」。
- 一个提交**只放一个**模块标签，取最主要的那个。确实跨模块时在 body 里说明，不要加第二个标签。
- **不写版本号**（`[V6.0.82]` 是反例）—— 版本是 tag 的事，不是提交标题的事。

---

## 四、与旧风格的关系

仓库历史里并存两种写法：较早的方括号式（48 笔，标签与空格都不统一）与较近的 `type(scope): subject`（conventional commits）。**新提交一律用本文的格式**，两套旧写法都不再用，历史不改写。

---

## 五、自查

提交前逐条过：

- [ ] 首行是 `[类型][模块] 英文标题`，方括号内外无空格，标题无句号？
- [ ] 类型在第二节那 8 个之内？
- [ ] 只有一个模块标签，且标题里没有版本号？
- [ ] `[what]` 写了；`[why]` / `[how]` 是「有内容才写」而不是硬凑的三段？
- [ ] body 是中文；`[how]` 引位置用的是 `文件:行`，而不是别的提交？
